# Batching rows into Google Sheets

Community post by **sheets_nadia** · answer by **dataops_leo**

## Question

We log every new Stripe payment to a Google Sheet, one row per run. On busy days the Google Sheets step fails with "Quota exceeded for write requests". Is there a better pattern?

## Accepted answer

That message comes from Google's own write quota, not from CloudFlow's API limit (which would show CF-429). Writing one row per event burns through the quota fast. Batch instead:

1. Change the workflow so it collects payments first, for example by writing them to a PostgreSQL table or keeping them in the trigger payload.
2. Add a second workflow on a schedule, every 5 or 10 minutes, that reads the collected payments and appends them to the sheet in a single Google Sheets step with many rows.
3. Keep each batch to a sensible size (we use 500 rows), so one append stays quick.

Fewer, larger writes stay well under the quota, and as a bonus you use fewer workflow runs per month.
