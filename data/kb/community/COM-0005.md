# Tips for moving webhooks to v2

Community post by **integrations_priya** · answer by **hooks_daniel**

## Question

We have about a dozen workflows triggered by webhooks v1 and we're on CloudFlow 4.4. With v1 deliveries stopping on 2026-12-01, what should we watch out for when moving to v2?

## Accepted answer

We moved 15 webhook workflows last month. What helped:

1. **Upgrade first.** Webhooks v2 needs CloudFlow 4.4 or later. Customers on 3.x or 4.0-4.3 have to upgrade before 2026-12-01.
2. **New URL per workflow.** The **Upgrade to v2** action on the webhook trigger gives a new `https://hooks.cloudflow.example/v2/<id>` URL. Keep a list of which sending system uses which URL.
3. **New signature.** Senders sign the raw request body: v2 expects HMAC-SHA256 in the `X-CloudFlow-Signature-256` header, while v1 used an HMAC-SHA1 hex digest in `X-CloudFlow-Signature`. Sign the raw body, not re-serialised JSON.
4. **Expect retries.** v2 retries a failed delivery up to 5 times with backoff, which v1 never did. The same event can then start more than one run, so make the workflow tolerate duplicates, for example by checking an order ID from the payload before creating records.
5. **Run both for a short while.** Point a test sender at v2 while production still uses v1, check the **Deliveries** log for accepted deliveries, then switch production well before the cut-off. From 2026-12-01 v1 URLs return HTTP 410 Gone.
