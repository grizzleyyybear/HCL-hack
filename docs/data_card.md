# Data card: CloudFlow synthetic data (Annex E)

One page by design. Full tables, prompt list and public-data notes: [data_card_details.md](data_card_details.md). Counted from the repo files on 2026-10-06.

| Field | What we did |
| --- | --- |
| **Purpose** | **Account data** (Annex C tables in SQLite) feeds the deterministic tools: usage against limits, invoices, refund eligibility, platform status. It has to cover all 4 plans, all 4 statuses and the exact boundaries the tools decide on. **Knowledge base** (73 documents): it has to cover 3.x and 4.x, outdated tickets that conflict with current docs, a future deprecation, a supersession, a prompt-injection ticket and policy articles that match the registry. Everything is invented: `@example.com` emails only, and cards stored as their last 4 digits. |
| **Generator** | KB (6 batches, 73 documents) and the 25 filler accounts: `claude-opus-5-5` (a Claude Code subagent standing in for the LLM) in replay mode. Temperature, calls and tokens are n/a: one saved reply per batch. Live mode sends the same prompts to Ollama at temperature 0.1, with up to 2 retries. The edge cases A1001–A1008, `plan_limits`, `platform_status` and all invoice amounts come from fixed specs in code, so the LLM never does money arithmetic. |
| **Prompts** | Verbatim in [`data/generation/prompts/`](../data/generation/prompts/): `gs_bil`, `policies_rn`, `api_trb`, `adv`, `tickets`, `community` and `accounts_v1`. Each is our improved Annex F prompt: shared rules + fact sheet ([`cloudflow_facts.md`](../data/generation/cloudflow_facts.md)) + batch brief + JSON schema, one category per batch, with IDs, versions, error codes, policy numbers and outdated tickets fixed in advance. |
| **Schema enforcement** | Pydantic on every row and document. KB: `SourceMeta`, `Document` / `Ticket`, plus manifest, section, ID-prefix, date, email and reserved-ID rules. Accounts: `FillerAccount`, with cross-field checks (no A9xxx, card_last4 exactly 4 digits, seats within the plan). Invalid output is re-asked up to 2 times, then either repaired in code with a log entry or dropped. The generator, validator and loader share the same row models. |
| **Row counts and distributions** | **31 accounts.** By plan: Free 5 · Pro 12 · Business 8 · Enterprise 6. By status: active 20 · past_due 4 · suspended 3 · cancelled 4. Versions: 4.3 ×12, 4.4 ×10, 4.2 ×6, 3.8 ×3. **62 usage rows** (2026-09 and 2026-10). **56 invoices** for the 26 non-Free accounts: 48 paid, 7 failed, 1 refunded; 43 USD, 13 INR. **4 plan_limits rows**, matching POL-LIMITS-001. **4 platform_status rows**, with workflow-engine degraded. **KB:** 34 articles, 3 policies, 2 release notes, 28 tickets, 6 community posts. |
| **Edge cases included** | **A1001** usage exactly at the Pro limit (10,000 runs, 300/min). **A1002** one over (10,001; 301/min, so it gets 429s). **A1003** past_due with a failed `card_declined` invoice. **A1004** duplicate charge (2 × 49.0 on 2026-10-01). **A1005** charged on the last day of the 14-day window (2026-09-22). **A1006** one day after it (2026-09-21). **A1007** suspended. **A1008** old version 3.8. |
| **Validation results** | `scripts/validate_accounts.py` → [`validation_report.txt`](../data/accounts/validation_report.txt): **0 violations** over all CSVs. It checks ID formats and reserved IDs, allowed values, `@example.com` only, card_last4 only and no full card anywhere, amount > 0, failure_reason only when failed, statuses consistent with invoices, and dates. `generate_kb.py` → [`kb_check.txt`](../data/generation/kb_check.txt): **PASS**: 73/73 valid, 13 seeded cases and every policy number check against the registry. |
| **What the LLM got wrong** | 4 of the 25 filler rows failed validation: **A9012** used a judge-reserved ID (dropped); **A1015** used a non-`example.com` email (domain repaired); **A1020** put a full card number in `card_last4` (cut to the last 4); **A1030** had negative `workflow_runs` (dropped). That is why A1012 and A1030 do not exist. The KB had 0 validation errors; the same gates apply to live runs of the 7B model. |
| **Known limitations** | Small and synthetic: 31 accounts and 73 documents. One reference date: 2026-10-06, with usage only for 2026-09/10, so A1005/A1006 move if `as_of_date` changes. The data was written by Claude, not the local model, so the slips above prove the gates work but do not measure the 7B model's error rate. The KB has no token counts. A1011 is over its API limit in 2026-09 without being a seeded case. Tone comes from 15 paraphrases, and theme counts are biased toward the queried tags. |
